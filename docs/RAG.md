## 파일 기반 RAG 해설과 유사 기출문제

기출문제 해설은 미리 생성한 임베딩 파일에서 관련 문제를 찾아 Groq에 참고 자료로 제공합니다. 추천 문제 최대 3개를 모달에서 연습할 수 있으며, 정답은 답안을 입력하고 확인한 뒤 표시됩니다. 연습 결과는 기존 퀴즈 순서·점수·북마크·오답·학습 진행률을 변경하지 않습니다.

DB 서버와 Docker는 필요하지 않습니다. 준비 단계에서 임베딩 파일을 생성하고, 실행 중에는 Node 서버가 그 파일을 읽어 현재 문제와 다른 문제의 코사인 유사도를 계산합니다. 검색 중에는 파일 쓰기와 임베딩 API 호출이 없습니다. AI 해설은 기존 Groq API를 사용합니다.

### 임베딩 파일 생성

Python 3.10 이상을 사용합니다. 프로젝트 루트에서 의존성을 설치합니다.

```powershell
python -m venv .venv
source .venv/Scripts/activate
pip install -r scripts/requirements-rag.txt
```

`.env`에 생성용 설정을 입력합니다. 아래 값은 기본 OpenAI 서버를 사용하는 예시이며, 다른 서버를 사용하면 주소·모델·차원을 해당 제공자에 맞게 변경합니다.

```dotenv
OPENAI_API_KEY=사용할_API_키
OPENAI_BASE_URL=https://api.openai.com/v1
EMBEDDING_MODEL=text-embedding-3-small
EMBEDDING_DIMENSIONS=1536
```

Python의 모델 생성은 다음 설정에 대응합니다. `OPENAI_BASE_URL`에는 `/v1` 등 제공자가 안내하는 API 기본 경로를 지정하며, 해당 서버는 `/embeddings`를 지원해야 합니다.

```python
model = OpenAIEmbeddings(
    model=MODEL_NAME,     # EMBEDDING_MODEL
    api_key=key,          # OPENAI_API_KEY
    base_url=BASE_URL,    # OPENAI_BASE_URL
    # 타임아웃, 배치 크기 등의 설정은 index_rag.py 참고
)
```

임베딩 생성 명령은 다음과 같습니다.

```powershell
python scripts/index_rag.py
```

최초 실행은 전체 문제를 생성하고 재실행은 변경된 문제만 임베딩합니다. 변경 없는 벡터를 재사용하고 삭제된 문제는 결과 파일에서 제거합니다. 생성 실패 시 이전 파일은 유지됩니다. 모델·차원·서버 주소를 바꾸려면 기존 JSON을 별도 보관하거나 제거한 뒤 다시 생성하세요.

결과는 `server/rag/data/questions.json`에 저장됩니다. 파일에는 ID·내용 해시·벡터·모델 설정을 저장하며 API 키는 포함하지 않습니다. API 키가 없으면 새 임베딩을 생성할 수 없습니다.

원본 데이터는 기존 `pstData`입니다. 검색 시 ID·내용 해시를 대조하여 수정되거나 삭제된 문제의 오래된 벡터를 제외합니다. 코드/개념 유형과 언어를 맞추고 자기 자신·동일 문서·낮은 유사도 결과를 제외합니다. 이미지 URL은 임베딩하지 않으며 현재 문제의 기존 이미지 해설은 유지합니다.

### 환경변수

| 환경변수 | 용도 / 기본값 |
| --- | --- |
| `RAG_ENABLED` | 기본 `true`, `false`이면 파일 검색 비활성화 |
| `RAG_MIN_SCORE` | 최소 코사인 유사도, 기본 0.45. 실제 문제로 조정 필요 |
| `RAG_TIMEOUT_MS` | 파일 읽기 제한 시간, 기본 5000ms |
| `EMBEDDING_MODEL` | 기본 `text-embedding-3-small`, 생성·실행 시 일치 필요 |
| `EMBEDDING_DIMENSIONS` | 기본 1536 (`text-embedding-3-large`는 생략 시 3072), 생성·실행 시 일치 필요 |
| `OPENAI_API_KEY` | **파일 생성 시에만 필요**, 실행 서버에는 불필요 |
| `OPENAI_BASE_URL` | 생성용 OpenAI 호환 API 기본 주소. 기본 `https://api.openai.com/v1`, 실행 서버에는 불필요 |
| `RAG_BATCH_SIZE` | 생성 배치 크기, 기본 32, 최대 64 |
| `RAG_INDEX_TIMEOUT_MS` | 생성 시 임베딩 API 제한 시간, 기본 60000ms |

외부 임베딩 모델을 사용할 때는 `EMBEDDING_MODEL`과 `EMBEDDING_DIMENSIONS`를 실제 모델에 맞춥니다. `dimensions` API 인자는 `text-embedding-3` 모델에만 전달하고, 다른 모델은 반환된 벡터의 차원을 검증합니다. 원문을 서버에 보내며 클라이언트가 코드를 분할하거나 자동으로 잘라내지 않습니다.

키에는 `VITE_` 접두사를 붙이지 마세요. JSON은 서버 전용 경로에 유지하며 `public`이나 `src/assets`에 넣지 않습니다.

### 검색 동작

검색은 생성된 JSON을 메모리에 읽어 재사용합니다. JSON을 다시 생성한 후에는 검색 프로세스를 재시작해야 합니다. 읽기 실패 시 30초 후 재시도하며, 파일이 없거나 잘못되면 기존 Groq 해설을 제공합니다.

`server/rag/search.js`의 `searchSimilarQuestions(query, options)`는 원본 문제 객체 또는 기존 문제 본문과 일치하는 문자열을 받습니다. 옵션은 `k`(기본 5), `year`, `round`, `excludeId`, `excludeQuestionId`, `signal`을 지원합니다. 임의의 새로운 자연어 질문은 저장된 벡터가 없어 검색하지 않습니다.

### Groq 해설 연결

기출문제 해설 요청은 다음 순서로 처리합니다.

1. 현재 문제의 벡터로 관련 기출문제를 최대 5개 검색합니다.
2. 관련 자료가 있으면 별도 Groq 호출에 현재 문제·저장된 정답·이미지만 전달해 정답과 핵심 개념을 검토합니다. 이 호출에는 검색 결과와 해설 초안을 제공하지 않습니다.
3. 최종 해설 프롬프트에 원본 문제, 검토 결과, 관련 문제의 본문·정답·출제 연도·회차·문항 번호를 넣습니다.
4. 활용한 근거를 핵심 개념 절에서 `관련 기출: [2025년 2회 3번] — 공통 개념과 차이` 형식으로 제시하도록 지시합니다. 추천 문제의 정답은 해설에 나열하지 않습니다.

검토 결과는 일치·모순·자료 부족으로 구분합니다. 저장된 정답과 검토 결과가 충돌하면 그 차이를 설명하고 원본 정답이나 채점을 임의 변경하지 않습니다. 이는 LLM을 통한 별도 검토이며, 실제 코드 실행·외부 자료 대조에 의한 정확성 보장은 아닙니다.

관련 자료가 있으면 Groq 호출은 검토와 해설 생성의 총 2회입니다. 별도 검토는 최대 20초로 제한하며 실패하거나 응답 형식이 잘못되면 검토 미완료 상태로 해설 생성을 계속합니다. 검색 결과가 없거나 검색에 실패하면 별도 검토 없이 기존 해설 호출 1회를 사용합니다. 이미지 문제는 두 단계 모두 기존 이미지 모델과 이미지를 사용합니다.

### 원본 데이터 연동

현재 Python 생성기는 기존 JS 데이터와 동일한 문서·해시를 얻기 위해 `scripts/export-rag.js`를 내부 호출합니다. 이 데이터 추출 단계에서는 프로젝트 환경의 `node` 명령을 사용합니다. 임베딩 API 호출과 결과 파일 저장은 Python에서 수행합니다.

### 개인화 학습 추천

기출문제 메뉴의 **학습 추천**에서 현재 브라우저에 저장된 오답·북마크·풀이 완료 기록을 바탕으로 미풀이 문제를 최대 3개 추천합니다. 오답과 유사한 문제를 우선하고, 같은 우선순위에서는 북마크 관심 여부와 유사도를 고려합니다. 각 문제에는 추천 기준이 된 오답 또는 북마크의 회차를 표시합니다.

최근 추가된 오답 최대 20개와 중복되지 않는 북마크 최대 10개를 검색 기준으로 사용합니다. 저장된 최근 답안이 정답이면 해당 문제를 오답 기준에서 제외합니다. 이미 푼 문제·오답 문제 자체·현재 진행 중인 문제·동일한 내용의 중복 문제는 추천하지 않습니다. 관련 미풀이 문제가 없거나 임베딩 파일을 사용할 수 없으면 안내를 표시합니다.

추천 화면에서 답안을 확인하면 기존 채점 방식으로 정답을 비교하고 점수·풀이 완료·오답 기록을 저장합니다. 진행 중이던 퀴즈의 문제 순서와 입력 중인 답안은 유지됩니다. AI 해설 모달 안의 기존 유사 문제 연습은 종전처럼 학습 기록에 반영되지 않습니다.

`POST /api/recommendations`에는 기출문제 ID 목록(`wrongQuestions`, `bookmarkedQuestions`, `solvedQuestions`, `excludeQuestionIds`)만 전달합니다. 사용자 답안 원문과 API 키는 보내지 않습니다. 이 요청은 저장된 벡터로만 검색하며 Groq·임베딩 API를 호출하거나 서버에 개인별 학습 기록을 저장하지 않습니다.

### 기출문제 기반 AI 튜터

기출문제 메뉴의 **AI 튜터**에 `OSPF와 RIP는 어떻게 다르고 시험에는 어떻게 출제됐어?`처럼 질문합니다. 등록된 개념의 명칭·동의어와 원문 텍스트로 관련 문항을 최대 6개 찾고, Groq가 해당 문항의 문제·보기·정답·연도·회차·문항 번호를 근거로 설명합니다. 새 질문의 임베딩을 생성하지 않으므로 임의의 자연어 질문에 대한 벡터 검색은 수행하지 않습니다. 등록되지 않은 개념은 원문 용어 검색만 사용하며 관련 근거를 찾지 못하면 그 사실을 안내합니다.

튜터는 일반적인 개념 설명과 실제 출제 사례를 구분하며 출제 사례에 `[2024년 1회 7번]`처럼 근거를 표시합니다. 서버는 근거 인용이 없거나 제공하지 않은 문항을 인용한 답변을 거절합니다. 이미지 내용은 튜터에 제공하지 않으므로 그림에만 있는 조건은 설명 근거로 삼지 않습니다. 답변에는 Groq 호출 1회가 사용되며, 임베딩 API 키나 새 임베딩 파일은 필요하지 않습니다.

`POST /api/tutor`에 `{ "query": "질문" }`을 전달하며 `answer`와 원본 문항 참조인 `sources`를 받습니다. 기존 문제 단위 해설·검토 기능과는 별개의 질의응답입니다.

### 개념별 출제 경향

기출문제 메뉴의 **출제 경향**에서 개념별 문항 수·출제 회차 수와 실제 집계한 문항 목록을 확인합니다. 연도를 선택하면 해당 연도의 원본 문항만 다시 집계합니다. 숫자는 벡터 검색 결과가 아니라 `server/rag/concepts.js`에서 분류한 원본 데이터의 합계입니다.

OSPF·RIP·조인·정규화·커버리지 등은 검토한 원본 문항 ID를 개념에 명시적으로 연결하고, C·Java·Python·SQL 코드 구분은 기존 언어 판별 함수를 사용합니다. 보기의 오답 항목에 용어가 등장했다는 이유만으로 개념 분류에 포함하지 않습니다. 분류 목록은 전체 문제를 아직 포괄하지 않으므로 화면에 분류 완료·미분류 문항 수를 표시합니다. 표시된 횟수는 **분류된 원본 자료에서 확인한 건수**이며 전체 시험의 확정 출제 횟수나 향후 출제 확률이 아닙니다. 한 문항에 여러 개념이 포함될 수 있으므로 개념별 수를 합산하지 않습니다.

원본 문항의 주제가 바뀌거나 새 문항이 추가되면 `conceptDefinitions`의 `sources` 분류도 검토해 갱신하세요. 이 분류는 임베딩 문서와 분리되어 있어 분류 변경만으로 재임베딩할 필요는 없습니다. `GET /api/trends`는 Groq 키 없이 사용할 수 있으며 LLM·임베딩 API를 호출하지 않습니다.
